# 09 · 图像与图表提取设计

> 目标：把论文里的**表格、图片、公式**从「不可检索」变成「可检索、可引用、可核对」，
> 同时不破坏现有正文链路（解析/切片/父子/引用见 [08](08-文档解析与切片链路.md)）。
>
> 本文是设计方案，不是已实现功能。落地时按第九节分阶段推进，每阶段有独立验收指标。

---

## 一、为什么做、先做什么

### 1.1 失败归因实验的结论

`eval/scripts/attribute_failures.py` 在 14 篇论文 / 2181 chunk / 188 条查询上的结果：

| 查询类型 | 数量 | Recall@5 | 可答率（top5 含答案） |
|---|---|---|---|
| 正文查询 | 140 | 72.9% | 85.0% |
| 图表查询 | 48 | 58.3% | 70.8% |

失败 35 条：排序失败 19（54%）、覆盖缺口 16（46%）。

拆分后结论完全不同：

- **正文问题**：瓶颈是排序（19 条排序失败 vs 2 条覆盖缺口），该做 BM25/rerank；
- **图表问题**：瓶颈是覆盖（14 条覆盖缺口 vs 0 条排序失败），而且集中在**图**：
  `figure 12`、`table 4`；
- 表格数值有相当一部分已被 pypdf 抽成纯文本，48 条图表查询里 34 条能由检索到的
  文本片段回答（含图注所在 chunk 本身），所以**表格的收益主要是准确率与可读性**，
  不是「从无到有」；
- 真正无法从文本恢复的是**图**：曲线数值、示意图结构、多面板截图。

### 1.2 目标与非目标

**目标：**

1. 图注、表格内容、图片内容进入索引，可被检索；
2. 引用能指到「第几页、哪个图/表」，前端能展示缩略图或表格片段；
3. 表格保持行列结构，数值可核对；
4. 与现有 `parentId`、`section`、`page`、`charStart/charEnd` 体系兼容。

**非目标（至少前三阶段不做）：**

- 通用版面理解大模型；
- 扫描件 OCR；
- 公式的完整语义还原（只做「可定位」）；
- 图表数值的自动读取（曲线取值、柱状图读数）作为默认能力。

## 二、设计原则

| 原则 | 说明 |
|---|---|
| 元素级建模 | 一个表 / 一张图 = 一个独立元素，不与正文 chunk 混在一起切 |
| 原文可回溯 | 每个元素必须有 `page + bbox`；引用可定位到原页区域 |
| 派生内容不冒充原文 | VLM 生成的图片描述标记 `derived=true`，引用必须指回原图，不能说成「论文原文」 |
| 先低成本覆盖，再视觉理解 | 图注/表格 markdown 不需要视觉模型；图片描述后置 |
| 不破坏现有链路 | 文本 chunk 的切分与召回基线保持不变，新元素走独立 `elementType` |

## 三、数据模型

### 3.1 Mongo：`file_elements`

```text
elementId     docId#t3 / docId#f2 / docId#eq5   元素唯一键
userId        归属用户
docId         文档 id
docTitle      文档标题
type          table | figure | formula
page          页码（1 起，0=未知）
bbox          [x0, y0, x1, y1]（PDF 坐标，左上为原点）
caption       图注/表注原文（可为空）
text          table: markdown；figure: 图片描述；formula: LaTeX 或原文
imagePath     裁剪图路径（figure 必需，table 可选）
derived       text 是否为模型生成（figure 描述=true，table markdown=false）
sectionPath   所在章节路径（复用 08 的章节识别）
parentId      所属父章节（复用 08）
charStart/End 图注在全文中的字符区间（用于和文本 chunk 对齐）
createdAt
```

索引：`(userId, docId)`、`(userId, elementId)`。

### 3.2 Milvus：`_<userId>_v4`

在 v3 字段基础上增加：

```text
elementId     VARCHAR(200)
elementType   VARCHAR(20)     text | table | figure | formula
page          INT64           复用
bbox          VARCHAR(120)    JSON 字符串，避免 Milvus 数组字段的版本兼容问题
caption       VARCHAR(1000)
```

其余 `parentId / chunkKey / section / charStart / charEnd` 保持 v3 语义。

**为什么 element 和 text 共用一个集合？**

- 现有混合检索、RRF、按用户隔离、删除逻辑都可以直接复用；
- 用 `elementType` 做过滤/加权即可；
- 只有当你需要给图片向量单独建索引（例如 CLIP）时，才拆独立集合。

### 3.3 原文存储

新增 `uploads-doc/` 保存原始 PDF（文件名用 docId，避免用户文件名注入路径）：

- 必要性：图片裁剪、页面预览、重新解析都依赖原文件；
- 体积：单文件 ≤5MB，按用户配额治理；
- 删除文件时同步删除原文件与所有裁剪图。

## 四、抽取流程

```
PDF
 │
 ▼
PyMuPDF 逐页解析
 ├─ page.get_text("dict") → blocks（text / image）
 ├─ page.find_tables()   → 表格区域（边框/对齐）
 └─ 视觉块（type=1）      → 图片区域 bbox
 │
 ▼
元素归类 + 图注关联
 ├─ text block  → 走 08 的正文链路（保持不变）
 ├─ table block → 区域级转 markdown，关联 Table N 图注
 ├─ figure block→ 裁剪 PNG，关联 Figure N 图注
 └─ formula    → 文本公式或区域裁剪（可选）
 │
 ▼
元素 chunk
 ├─ table : caption + markdown（超长按行组切，重复表头）
 ├─ figure: caption + VLM 描述
 └─ formula: caption + LaTeX
 │
 ├──► Mongo file_elements
 └──► Milvus v4（elementType=table|figure|formula）
```

### 4.1 解析器选型

| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| pypdf（现状） | 快、依赖小 | 无版面、无 bbox、表格乱序 | 保留为正文文本基线 |
| pdfplumber 整页表格 | 表格识别成熟 | 双栏按 top→x 排序，整页解析会交错，实测召回从 66.9%→48.5% | **禁止整页使用** |
| PyMuPDF（fitz） | 有 block/bbox/图片对象，`find_tables` 可区域级使用，速度快 | 复杂表格/合并单元格仍需兜底 | **主解析器** |
| Docling / Camelot | 表格结构更强 | 依赖重、速度慢、与现有轻量链路不匹配 | 作为离线实验对照 |

**结论：** 正文仍可先用 pypdf；图表元素用 PyMuPDF 做**区域级**抽取。若 PyMuPDF 的正文
阅读顺序在双栏论文上优于 pypdf，再整体切换，并用 08 的验收指标回归。

### 4.2 表格

区域级处理步骤：

1. 用边框线或文本对齐聚类出候选表格区域；
2. 区域内按行/列投影切分单元格；
3. 检测表头行（首行加粗/重复率/全列非空），生成 markdown；
4. 合并单元格用空串占位，保持列数一致；
5. 校验：列数稳定、数值列占比、行数 ≥ 2；不通过则降级为「区域原文」，不要硬造表格；
6. 跨页表格：按表头 + 编号合并为一个元素，`page` 记起始页，`bbox` 记首页区域。

输出示例：

```markdown
| Model | BLEU (EN-DE) | BLEU (EN-FR) | Training Cost |
|---|---|---|---|
| Transformer (base) | 27.3 | 38.1 | 3.3e18 |
| ... | ... | ... | ... |
```

### 4.3 图注关联

- 用正则 `^\s*(Table|Figure|Fig\.)\s*(\d+)[\.:]` 找图注行；
- 在同一页、同一栏内，选择与元素 bbox 最近的图注（图上表下是常见约定，但不绝对）；
- 距离阈值按页面高度比例（如 ≤ 15% 页高），超过则标记 `caption=""`、`captionConfidence=low`；
- 一个图注最多绑定一个元素；多面板图（Figure 3a/3b）按 `Figure 3` 归并，面板信息写进描述。

### 4.4 图片

- 栅格图：直接按 bbox 裁剪，200 DPI 存 PNG；
- 矢量图（架构图/流程图常为矢量）：把 bbox 区域**渲染**成图片，而不是尝试解析图元；
- 裁剪图路径：`uploads-doc/<docId>/fig_<n>.png`；
- 可选：生成缩略图（宽 320px）供前端卡片使用。

### 4.5 图片描述（VLM）

入库时为每张图生成 200~400 字描述，要求：

```text
你在描述一篇论文中的图。只描述图中确实可见的内容：
1. 图的类型（折线/柱状/架构图/示意图/截图）；
2. 坐标轴、图例、分组；
3. 可读出的关键数值或趋势（不确定就写“约”“无法精确读取”）；
4. 不要补充图外知识，不要推断作者结论。
输出 JSON：{"description": "...", "uncertain": ["..."]}
```

约束：

- 描述标记 `derived=true`，引用卡片明确写「图注 + 图像描述（AI 生成）」；
- 数值不确定时保留 `uncertain` 列表，生成阶段提示模型不要给出精确值；
- 描述只用于检索与概览，**不能作为论文原文引用**。

### 4.6 公式（低优先级）

- 行内/行间公式先用正则从文本中提取，保留 `charStart/charEnd`；
- 区域公式可裁剪为图片，`type=formula`，描述只写「公式区域，含 …」；
- 不在前两阶段做 LaTeX 语义重建。

## 五、切片与索引

### 5.1 元素级切分

| 元素 | chunk 组成 | 切分规则 |
|---|---|---|
| table | `Table N: caption` + markdown | 超过 2000 字按行组切，每块重复表头；`elementId` 相同，用 `chunkIndex` 区分 |
| figure | `Figure N: caption` + 描述 | 描述通常 < 500 字，不切 |
| formula | caption + LaTeX | 不切 |

关键：**元素 chunk 不与正文 chunk 合并**，避免表格数值污染正文语义检索，反之亦然。

### 5.2 元数据

- `parentId`：复用 08 的章节父文档，便于回表上下文；
- `elementType`：检索侧可过滤/加权；
- `page/bbox`：引用定位；
- `charStart/charEnd`：图注在全文中的位置，用于和正文 chunk 对齐。

### 5.3 父子上下文的使用差异

| 类型 | 生成时上下文 |
|---|---|
| 正文 chunk | 父章节 ± 600 字窗口（现状） |
| table chunk | **不扩窗口**，表格本身已自包含；需要时补 caption 与上一段解释 |
| figure chunk | **不扩窗口**，caption + 描述即可；避免把正文推测混进图的引用 |

## 六、检索与生成

### 6.1 检索

沿用「向量 + 关键词 RRF」，新增 element 结果后有两种策略：

| 策略 | 做法 | 适用 |
|---|---|---|
| A. 统一召回（推荐先做） | text/table/figure 同池检索，`elementType` 只作为展示字段 | 改动最小，直接复用现有 RRF |
| B. 类型感知 | 查询含「表/图/数值/对比」等线索时，对 table/figure 加权或先过滤 | 需要查询分类器，后置 |

先做 A，用失败归因实验验证 element 是否真的进入 top5；B 在 A 的指标稳定后再加。

### 6.2 生成

提示词增加元素规则：

- 表格数值必须来自 table chunk，引用标 `[N]`，不得改写数字；
- 图片结论必须注明「图中显示 / 根据图像描述」，描述不确定时明确说明无法读出精确值；
- 公式引用保留原式，不做等价变形；
- 不允许把「图像描述」说成「论文原文」。

### 6.3 引用与前端

`citations` 增加字段：

```json
{
  "index": 1,
  "elementType": "table",
  "docTitle": "...",
  "section": "3 Method",
  "page": 5,
  "bbox": [72, 310, 520, 480],
  "caption": "Table 2: ...",
  "snippet": "...",
  "text": "...",
  "previewUrl": "/open-doc/<docId>/elements/<elementId>.png"
}
```

前端卡片：

- table：展示 markdown 表格预览（可折叠），点击「查看原页」定位；
- figure：展示裁剪缩略图 + caption，点击放大；
- 正文引用保持现状；
- 角标 `[N]` 仍然按 fragment 编号，element 与 text 共用一套编号。

### 6.4 页面预览接口

```text
GET /file_management/{docId}/page?page=5          → 整页渲染图（便于人工核对）
GET /file_management/{docId}/element/{elementId}  → 元素裁剪图
```

接口需鉴权并校验 `docId` 归属；返回 `image/png` 或短期签名 URL。

## 八、评测方案

现有 `attribute_failures.py` 扩展第三类查询：

| 查询来源 | 金标 | 指标 |
|---|---|---|
| chunk 文本 | 源 chunk | Recall@5、可答率（现状） |
| 图表标题 | 图注 chunk | Recall@5、可答率（现状） |
| **表格单元格/行** | table element | `ElementRecall@5`、`CellAccuracy`（行/列/数值是否完全一致） |
| **图片描述问题** | figure element | `FigureAnswerable`（top5 中是否有该图）、人工抽查 |

新增指标：

1. **ElementRecall@5**：table/figure 元素是否进入 top5；
2. **CellAccuracy**：回答中的数值与表格单元格逐项比对；
3. **CitationAccuracy**：`[N]` 指向的元素是否真的包含答案句/数值；
4. **FigureAnswerable**：问题是否可由「图注 + 描述」回答，人工抽 50 条复核；
5. **回归**：正文查询 Recall@5 不低于 72.9%。

评测注意：

- **金标不能用 VLM 描述生成**，否则测的是描述模型而不是检索；
- 表格问题的金标要精确到单元格，不能只用「表所在 chunk」；
- 图片问题的金标是 element，允许「图注 + 描述」共同回答。

## 九、分阶段落地

| 阶段 | 内容 | 产出 | 验收 |
|---|---|---|---|
| **P0 解析基线** | 用 PyMuPDF 重抽正文与 bbox，与 pypdf 对比阅读顺序/页码/标题识别 | 解析对比报告 | 正文 Recall@5 不下降；`page` 抽样正确 |
| **P1 图注 + 表格** | caption 关联、区域级表格转 markdown、element chunk 入库、引用字段 | `file_elements` + v4 + 前端表格卡片 | `coverage_table` 下降；CellAccuracy 抽样 ≥90% |

| **P3 进阶** | 表格单元格 QA、图表读数、图片向量（CLIP）、公式结构化 | 可选能力 | 按业务收益评估，不阻塞主线 |

每阶段都必须重跑 `attribute_failures.py`，并记录四类指标的 before/after。

## 十、风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 版面误判 | 把正文当表格、把页眉当图注 | 区域校验 + 置信度；低置信度降级为文本，不硬造 |
| 双栏交错 | 左右栏文本混排 | 禁止整页表格解析；按栏/区域切分 |
| 合并单元格 | markdown 列错位 | 空串占位 + 列数校验；失败则存区域原文 |
| 矢量图无栅格 | 裁剪为空 | 按 bbox 渲染，而不是 `get_images()` |
| VLM 幻觉 | 描述编造数值/结论 | 描述标 `derived`；不确定值进 `uncertain`；生成阶段禁止精确引用 |
| 成本/延迟 | 入库时每图一次视觉调用 | 异步队列、失败重试、描述缓存；先只处理 figure |
| 存储增长 | 原文件 + 裁剪图 | 按用户配额；裁剪图可重建，允许清理 |
| 引用错位 | `[N]` 指到相邻元素 | `bbox` 与 `charStart` 双锚点；引用卡片展示原页 |
| 破坏正文链路 | 表格文本混入正文召回 | element 与 text 分离；A/B 回归 |

## 十一、验收底线

上线前至少满足：

1. 正文查询 Recall@5 不低于 72.9%，可答率不低于 85%；
2. 图表查询的覆盖缺口从 46% 降到 25% 以下，其中 figure 缺口明显下降；
3. 抽样 50 条表格回答，数值与单元格一致率 ≥ 90%；
4. 抽样 50 条带引用的回答，`[N]` 指向正确率 ≥ 95%；
5. 删除文件后，原文件、裁剪图、`file_elements`、Milvus v4 均无残留；
6. 任何新解析器/切分改动都能通过 `reindex_kb.py --prune-legacy` 完整重建。
